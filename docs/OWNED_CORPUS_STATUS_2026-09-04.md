`validation.passed=true`는 JSON 내부 산술·근거 연결 검증을 통과했다는 뜻일 뿐,
원문 표의 열 해석과 주택형별 선택비용까지 사람이 확인했다는 뜻이 아닙니다. 실제
최근 30일 PDF-backed 20개 공고·117개 tuple의 별도 의미 감사를 수행한 결과,
기존 수동 검수본 1개 외에는 자동 초안을 그대로 승격할 수 없었습니다. 무료 발코니를
유상 옵션으로 읽는 경우, 다른 주택형 행 연결, 선택옵션 누락, 만 원 미만 금액의
반올림, 대출·별도조달 회차 배분 누락이 확인됐기 때문입니다.

따라서 이번 점검에서 자동 승격 수를 부풀리지 않고 다음처럼 처리했습니다.

- 기존 exact `REVIEWED` 1개는 보존하고 새 자동 초안으로 덮어쓰지 않음
- 159개 모두 사람 검수용 source-locked draft/checklist/승인 양식 준비
- 만 원 미만 원문 금액은 정수 만 원으로 반올림하지 않고 `null`로 기권하도록 보강
- 추가비용 표가 있는데 결과가 비어 있으면 검증 실패와 blocking HOLD를 생성
- 현 스키마로 무손실 표현할 수 없는 대상은 승인 후보에서 제외

## 주택형별 자동추출과 사람 검수

`scripts/run_owned_corpus_extraction.py`는 159개 PDF-backed tuple을 정확한 주택형과
분양가를 넣어 순차 분석합니다. 출력은 항상 `AUTO_EXTRACTED` 또는
`NEEDS_REVIEW`이며 자동으로 `REVIEWED`를 만들지 않습니다.

`prepare-review-batch`는 각 tuple마다 다음 산출물을 만듭니다.

- 편집 가능한 source-locked 추출 초안
- 납부구조·중도금 금융조건·추가비용·위험조항·HOLD를 포함한 검수표
- PENDING 승인 양식
- inventory·PDF·자동추출 artifact·초안의 SHA-256 잠금

승인 단계는 원본 PDF와 정확한 주택형·가격·추가비용 적용 범위를 사람이 직접
확인해야 합니다. 배치 파일의 차단 사유나 버전만 수정해서는 승인되지 않으며,
원본 PDF 변경·중복 `REVIEWED`·시간대 없는 검수 시각·비정규화 주택형도 실패합니다.

## AUTO를 줄이는 실제 순서

1. 백엔드가 현재 노출할 공고별 fresh PDF를 AI에 한 번 전달합니다.
2. AI 서버가 URL을 기록하지 않고 exact PDF SHA-256, 페이지 수, 주택형·분양가와
   자동결과를 캡처합니다.
3. 자동 오류를 교정하고 원문·주택형·추가비용 적용범위를 항목별로 대조합니다.
4. 실제 검수자가 승인한 exact tuple만 `REVIEWED` allowlist에 추가합니다.

공고 ID만 같고 PDF가 다르거나, 주택형·분양가 중 하나라도 다르면 기존 검수 상태를
상속하지 않습니다. 이것이 신규 공고에서 `AUTO_EXTRACTED`가 나오는 정상적인 이유이며,
원본을 한 번도 전달받지 않은 상태에서는 AI 서버만으로 없앨 수 없습니다.
