# 아키텍처와 책임 경계

## 제품 흐름

`crawler → AI 근거 데이터 → backend 자금흐름 계산 → frontend 자금 완주 지도`

Get-MyHome 전체 제품은 청약 당첨 이후 입주까지의 자금 단절을 찾는 금융 리스크 엔진입니다. 이 저장소의 AI는 엔진 전체가 아니라, 공공 API에 없는 공고문 금융조건을 안전하게 공급하는 증거 계층입니다.

## 한 줄 책임

`주어진 공고문 PDF → 근거가 있는 구조화 데이터 → 자동 검증 → 사람 검수본`을 만든다.

## 컴포넌트별 책임

| 컴포넌트 | 책임 | 하지 않는 일 |
| --- | --- | --- |
| crawler | 청약홈 공고 탐색, PDF 다운로드, S3 저장, pre-signed URL 생성 | PDF 내용 판단 |
| AI_model | 전달받은 URL 즉시 수령 또는 로컬 PDF 로드, 페이지 텍스트화, 후보 페이지 선별, 구조화 추출, 고정 검증, 검수 파일 생성 | 청약홈 크롤링, 대출 자격·한도 계산 |
| backend | 사용자 조건·규칙표·AI 검수본 결합, 납부 타임라인과 최초 자금 단절 구간·부족액·확정도 계산 | PDF 자유 해석 |
| frontend | 입력·판정·근거·HOLD 질문 표시 | 금융 규칙 계산 |

## 배치 우선 흐름

1. 로컬 PDF 또는 crawler의 pre-signed URL을 입력받는다.
2. URL이면 만료 전에 즉시 메모리로 수령한다. 원 URL 전체는 로그에 남기지 않는다.
3. `pdftotext -layout`으로 물리 페이지 번호를 유지한 텍스트를 만든다.
4. 계약·대출·추가비용 카테고리별 후보 페이지와 인접 페이지를 모은다.
5. AI Structured Output으로 `ExtractionDraft`를 만든다.
6. Python 고정식으로 비율·정액·회차·날짜·근거를 다시 검증한다.
7. 검증값으로만 HOLD와 고정 요약문을 만든다.
8. `AUTO_EXTRACTED` 결과와 검수표를 저장한다.
9. 사람이 PDF 원문과 대조해 승인·수정한 뒤 `REVIEWED` 결과를 별도 저장한다.
10. API는 fresh PDF의 SHA-256과 공고·주택형·분양가가 모두 같은 `REVIEWED` 결과를 모델 호출 전에 찾아 반환한다.
11. exact 검수본이 없으면 `AUTO_EXTRACTED`를 반환하고 backend는 사용자 계산을 HOLD한다.

사전 분석·저장 키는 `(source_sha256, complex_id, unit_type_id, sale_price_manwon)`입니다. backend의
각 주택형 최고가를 기준으로 보수적으로 분석하며, 사용자 요청 시 모델을 다시 호출하지
않고 동일 키의 검수본을 읽습니다. 동·층별 정확가격을 받기 전까지는 최종 화면에
"주택형 최고가 기준"을 표시합니다.

AI의 `analysis_status=READY|PARTIAL|HOLD`는 문서 데이터의 완결성을 뜻합니다. backend의 `funding_status=OK|GAP|BLOCK|HOLD`는 사용자 조건을 결합한 자금판정이며 서로 다른 상태입니다.

자납 총비율은 확인됐지만 회차별 배분이 공고문에 없으면 backend는 특정 날짜를 만들지 않습니다. 이때 결과는 `중도금 구간/HOLD`로 표현하고, 정확한 최초 단절 날짜는 회차별 배분 근거가 있을 때만 제공합니다.

## API 위치

HTTP API가 필요하면 `POST /api/analyze`가 위 배치 파이프라인을 그대로 호출합니다. API가 별도 분석 로직을 갖지 않습니다. 서버 배포 여부와 무관하게 골든 테스트와 검수는 배치 명령으로 재현할 수 있어야 합니다.

## 재현성 기준

- 스키마 버전, 프롬프트 버전, 모델명, PDF SHA-256, 후보 페이지 목록을 결과에 남긴다.
- 동일한 자동 추출이 보장된다는 뜻이 아니라, 동일한 검수 완료 JSON을 backend에 넣으면 같은 판정이 나와야 한다는 뜻이다.
- 모델이 바뀌면 골든셋 회귀 평가를 다시 실행한다.
