# legacy 호환 응답과 AI 정본 계약의 차이

## 결론

AI 내부 정본을 현재 Java DTO에 맞춰 축소하면 실제 공고를 오계산할 수 있습니다. 정본은 보존하고, 임시 호환 응답은 별도 어댑터에서만 만듭니다.

## 확인된 차이

| 항목 | AI 정본 v0.3 | `/api/analyze/legacy` 축소 규격 |
| --- | --- | --- |
| JSON 이름 | snake_case | 실제 RestClient는 camelCase만 정상 파싱 |
| 비율 기준 | 모두 총 분양가 대비 | `interimLoanRatio`만 중도금 내부 비율 |
| 정액 납부 | 지원 | 미지원 |
| 자납 | 비율·정액 명시 | 별도 필드 없음 |
| 잔금 비율 | 실제값 사용 | 계약금·중도금으로 다시 계산 |
| 날짜 | 정확일·예정월·원문 | 정확한 날짜 문자열 하나 |
| 추가비용 | 주택형·포함 여부·여러 회차 | 모든 비용을 잔금에 합산 |
| 불확실성 | null+HOLD | 개별 null이 0으로 계산될 수 있음 |
| 근거·요약 | 전달 | 무시 |

특히 `중도금 60%, 대출 40%, 자납 20%`를 legacy 형태로 축소하면 40%를 중도금
내부 비율로 오해해 24%로 재계산할 수 있습니다. 따라서 정본을 legacy 응답에 무리하게
담지 않는 것이 이 문서의 목적입니다.

## 안전한 임시 정책

- `/api/analyze`는 v0.3 정본을 반환합니다.
- `/api/analyze/legacy`는 현재 DTO로 안전하게 표현 가능한 경우만 camelCase 응답을 만듭니다.
- 정액 납부, 비정수 변환, 핵심 null 등 손실이 생기는 경우 legacy 응답의 `paymentSchedule`을 null로 내려 잘못된 계산을 막습니다.
- 선택비용·분양가 포함비용·여러 회차 비용은 legacy `additionalCosts`에 넣지 않습니다.

기존 backend 저장소는 이 문서 작업에서 수정하지 않습니다. 정본 v0.3을 소비할지,
legacy 응답을 유지할지, advisory만 별도 사용할지는 향후 팀 선택입니다.
